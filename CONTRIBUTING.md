# Contribuindo

Obrigado por considerar contribuir com este projeto! 🎉
Toda ajuda é bem-vinda, seja relatando problemas, sugerindo melhorias ou enviando código.

Este documento descreve algumas diretrizes para facilitar contribuições.

---

# Como Contribuir

Você pode contribuir de várias maneiras:

* Relatando **bugs**
* Sugerindo **novas funcionalidades**
* Melhorando a **documentação**
* Enviando **correções ou melhorias no código**

---

# Reportando Bugs

Se você encontrar um problema, abra uma **Issue** no repositório.

Antes de abrir uma nova issue:

1. Verifique se o problema já foi reportado.
2. Descreva o problema de forma clara.
3. Inclua os passos para reproduzir o erro.
4. Se possível, inclua logs ou capturas de tela.

Exemplo de descrição de bug:

```text
Descrição do problema:
Explique o que aconteceu.

Passos para reproduzir:
1. Acesse ...
2. Clique em ...
3. O erro acontece

Comportamento esperado:
Explique o que deveria acontecer.

Ambiente:
- Sistema operacional:
- Navegador:
- Versão:
```

---

# Sugerindo Melhorias

Sugestões são muito bem-vindas!

Ao sugerir uma melhoria, tente incluir:

* Descrição clara da ideia
* Qual problema ela resolve
* Possível forma de implementação (opcional)

---

# Fluxo de Contribuição

Se você quiser contribuir com código:

### 1. Faça um Fork do repositório

Clique no botão **Fork** no GitHub.

### 2. Clone o seu fork

```bash
git clone https://github.com/SEU_USUARIO/NOME_DO_REPOSITORIO.git
```

### 3. Crie uma nova branch

```bash
git checkout -b feature/minha-nova-funcionalidade
```

### 4. Faça suas alterações

Implemente a melhoria ou correção.

### 5. Faça o commit das alterações

```bash
git commit -m "feat: adiciona nova funcionalidade"
```

### 6. Envie para o seu fork

```bash
git push origin feature/minha-nova-funcionalidade
```

### 7. Abra um Pull Request

Crie um **Pull Request** para a branch `main` deste repositório.

---

# Diretrizes para Pull Requests

Antes de enviar um PR, verifique:

* Se o código funciona corretamente
* Se as mudanças são claras e bem descritas
* Se a alteração resolve o problema proposto
* Se a documentação precisa ser atualizada

Prefira **PRs pequenos e objetivos**.

---

# Padrões de Código

Tente seguir o estilo de código já utilizado no projeto.

Boas práticas:

* Use nomes de variáveis claros
* Escreva código simples e legível
* Documente trechos complexos
* Evite mudanças desnecessárias

---

# Segurança

Se você encontrar uma **falha de segurança**, evite abrir uma issue pública.

Entre em contato diretamente com o mantenedor do projeto.

---

# Dúvidas

Se tiver dúvidas sobre como contribuir, fique à vontade para abrir uma issue.
